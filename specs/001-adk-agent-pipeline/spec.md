## User Scenarios & Testing *(mandatory)*

### User Story 1 - End-to-End Discovery, Visual Card Generation, AI Synthesis, and LinkedIn Publication (Priority: P1)

As a content creator and industry observer, I want an autonomous agent pipeline built on Google's Agent Development Kit (ADK) that sequentially coordinates tweet discovery from monitored profiles, captures a clean visual screenshot card, synthesizes an informed perspective, and publishes the media post directly to LinkedIn, so that I can maintain an active professional voice with zero manual procedural scripting.

**Why this priority**: Delivers the primary end-to-end value proposition. Establishing the complete sequential flow across the agent architecture provides a functional Minimum Viable Product (MVP) achieving parity with the reference project while transitioning to an agentic development model.

**Independent Test**: Can be tested by configuring a monitored account that has posted within the last 12 hours, running the ADK sequential agent pipeline, and verifying that the final post containing both the visual card and synthesized commentary appears on the authenticated LinkedIn profile.

**Acceptance Scenarios**:

1. **Given** valid source session credentials and an authorized LinkedIn profile, **When** the ADK sequential agent workflow executes and discovers an eligible tweet from a monitored account published in the last 12 hours, **Then** the tweet is rendered as a clean visual image, punchy opinionated commentary is generated by the AI model, and the post is published to LinkedIn with both commentary text and the image attachment.
2. **Given** a successfully published LinkedIn post, **When** inspecting the publication response, **Then** the system receives a valid publication confirmation and logs the unique LinkedIn post identifier.

---

### User Story 2 - Scheduled & Autonomous Periodic Execution (Priority: P2)

As a creator operating a regular content cadence, I want the ADK agent pipeline to run autonomously on a recurring schedule without manual command-line invocations, evaluating monitored accounts at designated intervals and processing eligible posts hands-free.

**Why this priority**: Transforms the pipeline from an on-demand manual utility into a hands-off, set-and-forget content engine that maintains a steady social presence.

**Independent Test**: Can be tested by configuring a recurring schedule trigger for the agent runner, verifying that the agent awakens on schedule, executes the sequential pipeline, posts qualifying content, and returns to an idle/dormant state between runs.

**Acceptance Scenarios**:

1. **Given** an active schedule configuration or external scheduler invocation, **When** triggered either as a single execution cycle or via the continuous in-process scheduler, **Then** the ADK agent runner initiates the sequential workflow automatically without human intervention.
2. **Given** a scheduled run where no qualifying tweets exist within the 12-hour recency window, **When** candidate timelines are scanned, **Then** the agent logs an informative no-op result and cleanly returns to wait for the next scheduled trigger.

---

### User Story 3 - Time-Window Filtering & Idempotency Duplicate Prevention (Priority: P3)

As a user running the pipeline repeatedly or on a schedule, I want the agent workflow to strictly limit ingestion to posts authored within the last 12 hours and persistently record all published posts, so that my professional network is never spammed with duplicate or stale content.

**Why this priority**: Essential safeguard for platform reputation, rate limit conservation, and idempotency across recurring autonomous runs.

**Independent Test**: Can be tested by running the agent workflow to post a tweet, triggering a subsequent run immediately, and confirming that the agent identifies the tweet in the persistent ledger and skips it without errors or repeated posts.

**Acceptance Scenarios**:

1. **Given** a monitored profile with tweets older than 12 hours, **When** the timeline ingestion agent executes, **Then** tweets older than 12 hours are filtered out from the processing pipeline.
2. **Given** a tweet published within the last 12 hours that is already present in the publication ledger, **When** the pipeline processes candidate tweets, **Then** the agent skips the existing tweet and terminates or advances to the next unposted item.

---

### User Story 4 - Interactive Staging, Preview & Editorial Review (Priority: P4)

As an editor who values brand safety, I want the ability to run or inspect the ADK agent workflow in an interactive staging/preview mode (such as via an agent web interface or dry-run evaluation) where I can review the captured image and synthesized commentary before authorizing live publication.

**Why this priority**: Provides editorial trust, quality verification of AI commentary, and visual review of rendered cards before publishing to a public professional audience.

**Independent Test**: Can be tested by invoking the pipeline in staging/preview mode, verifying that the visual card and commentary are generated and inspectable in the session state/local storage, while zero network requests are dispatched to LinkedIn publishing endpoints.

**Acceptance Scenarios**:

1. **Given** on-demand manual execution, **When** an eligible tweet is processed, **Then** the system displays the preview (visual asset path and synthesized commentary) and prompts the operator for confirmation before dispatching to LinkedIn.
2. **Given** scheduled unattended execution, **When** an eligible tweet is processed, **Then** the pipeline proceeds directly to LinkedIn publication without waiting for interactive input.
3. **Given** dry-run mode is enabled, **When** executed either manually or scheduled, **Then** visual card rendering and commentary synthesis complete but LinkedIn publication is withheld.

---

### Edge Cases

- **No Qualifying Content in Window**: When monitored accounts have not posted within the last 12 hours, the agent pipeline logs an informative notice ("No new tweets found in the 12-hour window") and cleanly completes the cycle with zero errors.
- **Source Authentication Invalidation**: If source platform session cookies expire or face rate limits, the ingestion agent catches the failure, logs actionable diagnostic guidance, and halts execution gracefully without corrupting pipeline state.
- **Visual Card Rendering Timeout**: If browser automation fails to load the tweet card or render the screenshot within a configured timeout, the pipeline aborts the cycle for that item, logs the diagnostic error, and prevents publishing an incomplete or broken post.
- **Generative AI Moderation or Unavailability**: If the generative model service is unreachable, times out, or triggers a content moderation filter, the agent preserves the captured card, records the diagnostic failure, and aborts the LinkedIn publish stage for that tweet.
- **LinkedIn Asset Upload / Publish Failure**: If asset registration, image upload, or post publishing encounters an API rejection or token expiration, the publication agent logs the error response, aborts the transaction, and ensures the tweet is not marked as published in the ledger.
- **Multiple Qualifying Posts in Window**: When multiple accounts or a single account post multiple tweets within the 12-hour window, the agent selects and processes the single most recent unposted tweet per execution cycle, leaving remaining unposted tweets available for subsequent runs.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST orchestrate the multi-step tweet-to-LinkedIn workflow using Google's Agent Development Kit (ADK) sequential agent architecture (`SequentialAgent`), coordinating discrete specialized agent/tool steps across a unified session state.
- **FR-002**: System MUST provide a dual-mode execution runner supporting both single-run on-demand execution (for external schedulers like cron or Windows Task Scheduler) and continuous in-process interval scheduling.
- **FR-003**: System MUST authenticate with Twitter/X using user-provided browser session credentials (`cookies.json`) without requiring official developer API keys.
- **FR-004**: System MUST load target Twitter accounts from configuration with support for dynamic overrides at execution time.
- **FR-005**: System MUST restrict candidate post ingestion strictly to original authored posts and quote posts created within the preceding 12 hours relative to execution start time, excluding conversational replies and retweets.
- **FR-006**: System MUST maintain an idempotency publication ledger in persistent storage (`state/sidekick.db`) recording source tweet IDs, author handles, publication timestamps, and LinkedIn post IDs to guarantee zero duplicate publications across agent runs.
- **FR-007**: System MUST render a clean, distraction-free visual screenshot card of the selected tweet using headless browser automation, hiding public vanity metrics (likes, retweets, views) and defaulting to dark theme.
- **FR-008**: System MUST synthesize minimalist, punchy opinionated commentary (1–2 concise sentences reflecting an informed professional perspective) based on the source post content using the Google Gemini model, with Google Search grounding enabled by default (and configurable to disable) to incorporate real-time web context.
- **FR-009**: System MUST register the visual screenshot asset, upload the binary image payload, and publish the post with attached image via the official LinkedIn UGC Posts API.
- **FR-010**: System MUST authenticate with the LinkedIn API using OAuth 2.0 member access credentials with required permissions (`w_member_social`, `openid`, `profile`) and the member's Person URN.
- **FR-011**: System MUST automatically publish qualifying posts during scheduled unattended execution, while providing an interactive confirmation prompt (`[y/N]`) and preview mode during on-demand manual execution, plus a dry-run mode to inhibit publication across any mode.
- **FR-012**: System MUST select and process the single most recent unposted qualifying tweet across monitored accounts per execution cycle while maintaining state continuity for subsequent cycles.
- **FR-013**: System MUST log structured diagnostic events and error states throughout all agent stages without leaving orphaned or corrupt database records.

### Key Entities

- **Monitored Profile**: Represents a target Twitter user account (username, user ID, monitoring status).
- **Source Tweet**: Represents a candidate post ingested from Twitter (tweet ID, author handle, text content, creation timestamp, media attachments, permalink URL).
- **Visual Asset**: Represents the captured image of the tweet (local file path, MIME type, dimensions, file size).
- **Synthesized Commentary**: Represents the AI-generated opinionated text crafted for the LinkedIn audience (1–2 concise punchy sentences, character count, minimal tone prompt).
- **LinkedIn Publication Record**: Represents the completed post transaction (internal ID, source tweet ID, LinkedIn digital media asset URN, LinkedIn post URN, publication timestamp, status).
- **Publication Ledger**: Persistent relational storage (`state/sidekick.db`) tracking published tweet IDs and execution history to guarantee idempotency across multiple runs.
- **Agent Workflow Session**: The shared runtime session state maintained by Google ADK across sequential agent steps, holding intermediate artifacts (selected tweet, visual asset path, synthesized text, publication status).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: End-to-end execution through all sequential agent stages (discovery, rendering, synthesis, and publishing) completes in under 60 seconds per post under standard network conditions.
- **SC-002**: 100% of published posts on LinkedIn successfully contain both the AI-synthesized commentary and the corresponding source visual screenshot attachment.
- **SC-003**: Zero duplicate posts are published to LinkedIn for any source post previously recorded in the persistent ledger.
- **SC-004**: 100% of processed posts strictly comply with the 12-hour recency window and monitored accounts list.
- **SC-005**: In preview/staging mode, 100% of visual assets and commentary are generated and inspectable with zero network requests dispatched to external LinkedIn publishing endpoints.
- **SC-006**: Scheduled autonomous agent runs execute on schedule and cleanly conclude or enter dormancy within 15 seconds when no new eligible posts are discovered.
- **SC-007**: Upon third-party service timeout or authentication failure, the agent halts within 15 seconds, reports actionable diagnostics, and prevents orphaned or corrupt database states.

## Assumptions

- **Architecture & Framework**: The application is developed as a multi-agent system utilizing Google's Agent Development Kit (`google-adk`), orchestrating workflow stages sequentially via `SequentialAgent` across shared session state, and accessible via ADK runner/web runtime (`adk web`).
- **Autonomous & Scheduled Execution**: Scheduled execution is orchestrated via an ADK runner or schedule trigger that periodically initiates the sequential pipeline.
- **Parity Baseline**: This initial specification achieves complete functional parity with the non-ADK reference implementation (`C:\Users\Amit Nagar\Documents\linkedIn-sidekick`), re-architected onto Google ADK agent primitives.
- **Twitter Authentication**: The user provides a valid browser cookie export (`cookies.json`) with active authentication for Twitter/X.
- **Content Filtering**: Standalone replies and pure retweets are excluded; original author posts and quote tweets are eligible.
- **Visual Capture**: Headless browser automation captures an isolated tweet card in dark mode with public metrics suppressed.
- **AI Model & Key**: Generative commentary utilizes the Gemini API (`gemini-3.8-flash` or configured Gemini model) via a user-configured `GEMINI_API_KEY` or `GOOGLE_API_KEY`.
- **LinkedIn Credentials**: The user provides valid LinkedIn OAuth 2.0 credentials (`LINKEDIN_ACCESS_TOKEN`, `LINKEDIN_PERSON_URN`) authorized with `w_member_social` permission.
- **Operating Environment**: The application runs in a Python 3.11+ environment with Playwright browser dependencies installed.
